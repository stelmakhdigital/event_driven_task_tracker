## Description
Одно из главных требований сервиса обработка >10K событий/час с гарантией доставки

## Solution
В качестве решения остановимся на Kafka c `replication_factor=3` и `acks=all`. Возможность реализации exactly-once доставки. Возможность хранения сообщений несколько дней для повторной отправки. Возможность горизонтального масштабирования новых партиций.

## Consequences
Альтернативы:
    - RabbitMQ (проще но хуже масштабируется для highload)
    - AWS и другие подобные cloud решения (дорого)

Из плюсов: 
    - гарантию доставки сообщений достигнем благодаря репликам и их синхронизации с acks=all
    - повысим доступность сервиса и отказоустойчивость системы

Из минусов:
    - репликация дает более высокую задержку (из-за репликаций сообщения по всем брокером до возврата подтверждения)
    - для репликации требуется больше места на диске (повлечет доп. расходы)
    - сложность настройке кластера и конфигурировании топиков с брокерами
